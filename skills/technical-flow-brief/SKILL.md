# 技术流程与 API 汇报

把技术事实变成能讲清楚的工程图册，而不是把函数名填进模板。默认保留紧凑红灰淡黄视觉，采用“总览 → 按阶段展开 → 共用与差异清单”；用户的指定页数、已有版式与阅读目的优先。

本 Skill 沉淀讲解与判定方法，不携带任何项目的事实结论，也不要求固定页数、固定泳道或固定三个 Engine。

## 按需读取

- 做流程页：读 [story-and-flow.md](references/story-and-flow.md)。
- 做接口对比、测试清单或从源码判定共用：读 [evidence-and-matrix.md](references/evidence-and-matrix.md)。
- 新建或调整版式：读 [visual-system.md](references/visual-system.md)；已有用户认可的版式优先。
- 交付前：读 [review-checklist.md](references/review-checklist.md)。
- 若环境有 **Presentations** 技能，用它处理可编辑 PPTX、备注、导出与渲染。本 Skill 不替代文件生成工具；缺失时说明可交付范围，不能把文字大纲声称为已完成 PPT。

## 工作顺序

1. **先定边界。** 记录版本、设备/后端、运行模式、入口、已存在资源、数据规模及排除项。修改已有 PPT 时先定位要改的页和构建脚本，保留用户已认可的流程和资产。
2. **先取证，再画图。** 建立“调用者 → 精确符号 → 所属模块/层 → 中文动作 → 输入/产物 → 条件 → 证据”。区分导出 API、内部方法、运行时 API、C++ 指令描述和硬件动作。声明存在、同名包装或未被调用的辅助函数都不是实际进入路径的证据。
3. **确定阅读结构。** 总览只保留主要跨层动作及资源/数据交接；复杂节点后页沿同一名称展开。跨页定位可以使用章节名；页码范围不是默认装饰，用户要求去掉时不再加回。
4. **用关系选图。** 跨层过程优先“横向阶段 × 纵向责任层”的流程图。调用层次用嵌套，资源去向用对象/边，双方握手用时序，条件用分支。不要用一串序号冒充调用顺序，也不要为了填满泳道给每格塞节点。
5. **每个 API 旁边写作用。** 至少说清动词和对象：获取什么、创建什么、交换什么、提交给谁。不要只写“处理”“初始化”“执行”。长解释、参数及源码依据放备注，但关键触发条件必须在正文。
6. **最后做测试矩阵。** 选择真正解释差异的比较轴。若算子共享框架、差异主要来自后端/Engine，就按后端分列，不重复放几列几乎相同的算子。先排全部共用，再排部分共用、各路径专用、特殊/兼容分支；不确定项独立列出。
7. **检查最终导出。** 渲染检查长函数名、条件、箭头和表格；对未请求改动的页比对原版。交付文件、适用范围及必要限制，不写构建日志。

## 不能省略的工程区别

- 获取资源 ≠ 创建物理资源；复用命中可跳过创建。不要把“第一次运行”当成所有层资源都不存在。
- 建链资源描述交换、算子参数一致性检查、用户数据搬运是三种动作，分别标对象与产物。
- Host 提交/入队 ≠ 设备实际完成；完成依赖用通知、事件、等待或回调说明。
- 共用控制框架 ≠ 共用数据原语；同一 API 也可有不同参数、Peer 数、句柄和对象数量。
- 提供某项能力 ≠ 当前路径调用；静态源码判定 ≠ 上板 trace；接口单测 ≠ 算子端到端正确性。
- 表中 `✓` 表示该路径在正文条件下涉及；`—` 表示限定路径不使用；未证实写“待核”。不使用 `✓冷`、`△扩` 这类需要反复解码的复合符号。

## 资源

- [api-matrix.mjs](scripts/api-matrix.mjs)：纯本地的矩阵数据校验、分组排序与状态映射，不猜测调用事实，不生成或上传 PPT。
- [matrix-example.json](assets/matrix-example.json)：虚构 API 的最小数据样例，用于理解输入格式，禁止作为项目事实。
- [test-api-matrix.mjs](scripts/test-api-matrix.mjs)：验证共用优先、特殊条件、未知状态和证据缺失检查。

使用示例：`node scripts/api-matrix.mjs assets/matrix-example.json`。脚本只输出校验后的 JSON；接入 PPT 生成器时仍需按真实材料重新填表。源码证据写“相对路径:行号 + 提交号”，公开包不携带机器绝对路径。
