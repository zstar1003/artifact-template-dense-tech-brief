# 按路径比较 API 与测试覆盖

## 先选择能解释差异的轴

算子、Engine、协议、设备代际、图/单算子模式是不同维度。先固定不比较的条件，再选择差异最大的轴。不要在算子各列几乎全勾时继续增加相同列；可换为后端/Engine，同时保留“不同算子仍须测最终数据结果”的边界。

Engine 名称只是一个例子。迁移到存储、编译器或推理框架时可以是 I/O 后端、编译后端、执行模式。不要写死为 AICPU、CCU、AIV，也不要把一个具体模式外推为整个后端家族。

## 证据分三级

1. **能力证据：** 头文件声明、支持列表。只能说明存在或可用，不能直接勾选本次路径。
2. **路径证据：** 入口选择、调用点、分支条件、被实际调用的包装层与实现。可以做限定范围的静态覆盖表。
3. **运行证据：** 带配置、版本、实际 Engine、算法和参数的 trace。才能声称某次运行命中。

不能把源码行数当调用次数。仅有定义但没有调用者的辅助方法，不计入实际路径。动态加载接口应同时检查能力判定和所选兼容分支。下层导出接口通过函数指针调用也算，但要追踪真实符号，不能按前缀猜归属。

## 表头与状态

推荐原生可编辑表格：

`功能类别 | 精确 API | 中文作用/产物 | 路径 A | 路径 B | 路径 C | 调用条件/测试点`

保留用户已有控制面/数据面功能分类；Engine 是比较列，不替代功能分类。不同来源的符号必要时再加“归属”列，或把非目标库的运行时 API 放到单独说明表。

- `✓`：在本表限定路径和条件下涉及，需要设计对应条件的用例。
- `—`：本表所选路径不经过，不等于实现永远不支持。
- `待核`：缺少足够证据；不能改成 `—`，也不能为了表格完整而打勾。

这些是测试覆盖口径，不是“每次必须调用”的判定。不使用 `✓冷`、`△扩`、`✓*` 等复合编码。直接写“资源不存在时创建”“默认超时能力支持时”“仅某类型分支”等中文。

## 排序

1. 全部路径有证据涉及的 API；带创建条件的共用接口仍属于共用。
2. 部分路径共用的 API。
3. 各路径专用接口，按表头路径顺序分组。
4. 特殊内存、兼容、回退、清理等专门分支。
5. 证据不足项及不应要求出现的接口，单独解释。

每个符号一行，避免同一个 API 在多个组重复计数。全部有勾的条目先排；条件写右列，不用模糊状态冲淡条件。分组是一种阅读排序，不是运行顺序。

## 一条 API 的最小事实记录

```text
owner：真正提供接口的模块
kind：导出 API / 内部方法 / 运行时 API / C++ 操作
category：功能类别
api：精确大小写、命名空间
purpose：动词 + 对象/产物
coverage：每条路径的状态、条件、证据
test：输入、产物、依赖或生命周期检查点
special：是否属于专门的特殊/兼容分支
```

脚本输入见 `../assets/matrix-example.json`。每个“使用”和“不使用”的判定都需自己的路径证据；未知可以没有证据，但必须写缺什么。校验器只能检查数据结构和排序，不能证明引用的源码支持结论。

## 测试点不是“函数出现过”

| API 类别 | 检查对象 |
|---|---|
| 域/上下文 | 域与 tag 隔离、配置、查找命中、正确存储位置 |
| 内存 | 地址范围、长度、版本、访问权限、远端归属 |
| 拓扑 | Rank/实例/Endpoint/协议与通道需求的对应 |
| 通道 | 获取/复用/创建区分、句柄、READY、交换描述 |
| 任务发射 | stream/Thread、Kernel ID、参数、提交与完成 |
| 数据搬运/归约 | 偏移、分片长度、类型/运算、最终结果 |
| 同步 | 发布/等待配对、槽位/掩码、依赖与超时 |
| 清理/回退 | 本轮新增资源范围、已有对象仍可用 |

用合成数据验证，不在报告中收集业务张量、访问 Token 或其他敏感原文。共用 API 的参数、对象数量及调度组合仍会变化，接口测试不能替代多个算子的集成测试。

## 不要强行统一数据面

有的后端直接提交队列原语；有的注册并发射指令 Kernel；有的通过另一个运行时启动设备核。若库只负责资源/地址准备，后续由运行时或设备 SDK 完成，就在边界处停止给本库打勾，并另表说明实际执行者。

模块 API 与同名内部方法不得互换。是否查询远端地址、取得访问描述、发起通知，要由相应分支的代码决定，而不是由“它们都要通信”推断。
