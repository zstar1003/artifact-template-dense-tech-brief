# 页面组合方式

先按要解释的关系选布局，再填内容。以下坐标对应保留的 1280 × 720 参考，可按内容微调；不是固定页序。

## 分层软件栈

参考：`../assets/preview.png`，PPTX 第 1 页。

适合总览、上下层 API 边界、资源归属。

- 纵向 4–5 层，每层一个细边界，不为每个 API 加大外框。
- 入口是紧凑的若干语义组，每项两行：API 家族 + 含义。
- 核心层先展示入口到执行的连续调用，再用连续短条补充 Executor / Template 职责。
- 公共资源层分成按职责组织的列组，列内名称和含义同排。
- 底部放真实的执行分支对照，并注明选择关系。

原参考区块 y/h：83/72、164/149、322/129、460/105、574/103。主要内容横向占满版心。

## 函数调用与层次

参考：`../assets/layouts/call-tree.png`，PPTX 第 4 页；较少阶段也可参考第 2 页。

- 2–4 个阶段列，每列头部写所属层/阶段。
- 列内紧排函数及释义。缩进表示子调用，编号用于查找。
- 箭头画在有证据的流程衔接处，不能用阶段标题箭头替代必须讲清楚的函数边界。
- 互斥、提前返回、缓存命中与条件调用写在对应条目旁；下方可用紧凑区块展开条件及回填对象。
- 父函数包住子函数、调用返回到上层继续执行，这些关系不要画成同层“函数 A 完成后才进入函数 B”的假时序。

## 能力或 API 矩阵

参考：`../assets/layouts/matrix.png`，PPTX 第 5 页。

- 使用原生表格，保留可编辑单元格。
- 表头与首列为浅灰，数据主体白底；只对特定差异格用淡黄。
- 较短的能力列居中，语义差异列留出较多宽度。
- 矩阵后面接公共 API 家族释义或证据，给出勾选的准确口径。
- 明确“支持/可能调用”与“每次都会执行”的差别。

## 并列执行路径

参考：`../assets/layouts/engine-comparison.png`，PPTX 第 6 页。

- 比较确实独立的执行引擎、部署方式或协议时使用 2–3 列。
- 同一列内按“资源准备”“执行/发射”分段，函数两行紧排。
- 不用“1/2/3”大色块或列间箭头暗示互斥路径串行执行。
- 同一行高度大体一致便于对照，但不为对齐编造函数或空阶段。
- 公共资源和差异条件可在底部形成连续短条。

原参考三列 x=28/440/852，w≈400，y=84，h=483；底部 y=576，h=101。

## 具体实例与参数流

参考：PPTX 第 7 页。

- 先给一条有源码依据的实例，按调用者/被调用者展示函数和语义。
- 下方使用原生表格说明参数从何而来、传给谁、改变什么。
- 最后紧凑列出归约/同步/批处理等相关变体。
- 兼容路径要有分支标记，不和正常路径混成必经步骤。

## 换主题时

可以应用到存储、编译器、网络、推理引擎、分布式调度等有明确层次和接口的主题。保留视觉关系，替换所有名称、例子、来源和说明。不要复制参考主题的函数名、提交号或结论。若材料以数据为主，用原生表和图；若是纯文字议题，可采用紧凑段落分组，不强行转成调用树。
