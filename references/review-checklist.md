# 紧凑技术汇报检查

- 总览的主要 API、责任层、交接对象与完成依赖清楚，细节沿同名阶段展开。
- 每个 API 有中文动词和对象，关键条件在正文；长释义与源码依据在备注。
- 获取不等于创建，资源交换不等于张量传输，Host 提交不等于设备完成。
- 箭头有真实语义与明确落点，不靠大序号、长蛇形线或过多交叉理解流程。
- 比较轴解释真实差异；全部共用在前，部分共用、专用、特殊和待核有清楚分组。
- 状态只用有定义的勾、横线、待核；没有“✓冷”一类含糊复合缩写。
- 静态路径、能力声明、实际运行有区别；内部方法和导出 API 不混用。
- 各 Engine 的数据执行主体按证据呈现，不因共用控制框架而强行统一数据面。
- 红灰淡黄稳定；间距与行数相称，图中保留必要路由空间，长 API 不截断、不自动缩成极小字。
- 最终导出已逐页检查；未要求修改的页与原版对比；图形和表格可编辑。
- 限制本地使用的照片不进入技能、Git 或公共预览，新增业务报告不默认打包发布。
- 报告实际完成的检查，不把渲染称为 PowerPoint 测试或硬件验证。
