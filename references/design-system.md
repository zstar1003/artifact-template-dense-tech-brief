# 紧凑技术汇报的视觉参数

参数取自用户认可的 v19，用于复现其密度与层级。下列几何和字体单位均为 **CSS px**，以 1280 × 720 为基准；不是 PowerPoint pt。换画布尺寸时按相同比例换算，不能把 px 数值直接当 pt。

## 版心与文字

| 项目 | 参考值 | 使用判断 |
|---|---|---|
| 页面 | 1280 × 720，16:9 | 新输出尊重用户指定尺寸 |
| 左右边距 | 28 | 内容宽 1224 |
| 主标题 | x=28，y=13，h=36，27 px，加粗 | 一行，主题明确，不写口号 |
| 副标题 | x=30，y=53，h=19，12.5 px | 解释范围或读图顺序，不重复标题 |
| 页码 | x=1216，y=54，w=34，h=17，10 px | 副标题留出空间，禁止碰撞 |
| 标题下线 | y=75，1 px | 中性色；正文从 y≈84 开始 |
| 正文区域 | y≈84–677 | 避免大空封面和宽阔标题带 |
| 页脚 | y=687 细线，文字 y=691 | 来源 8.4 px，最多一行 |
| 字体 | PingFang SC | 若环境缺失，确认可用的中文字体并重渲染，不能默默缺字 |
| 组标题 | 15 px，加粗 | 浅灰条，高 24 px |
| 普通正文 | 12–14 px | 清晰优先，紧排不等于小字 |
| 函数名 | 12–13 px，加粗 | 极长 API 可约 10.5–11.5，优先调整列宽/显式换行 |
| 函数说明 | 11.8–13 px | 与 API 紧邻，不用极浅灰小字 |

若长名称需要两行，增加该条高度并让后续内容下移。不要用隐藏截断、超出文本框或自动缩成极小字处理。8–9 px 仅用于源码脚注，不作为大段正文。

## 间距

| 对象 | 几何参考 |
|---|---|
| 组框 | 0.7–1 px 细边框，无圆角、无阴影 |
| 组标题带 | 高 24 px |
| 组内左/右边距 | 6 px |
| 正文距组顶部 | 29 px，包含组标题带 |
| 同组行间隔 | 常用 2 px，可在 2–4 px 内调整 |
| 区块/列间隔 | 常用 8–10 px |
| 单行短条 | 高 25–31 px |
| 两行函数条 | 高 34–39 px；复杂说明可到 42 px |
| 条内左右边距 | 5 px |
| 条内上/下边距 | 约 1–2 px |
| 原生表格 | 表头高 29–35 px，常规单行 29–33 px；两行约 35–44 px |

不要机械拉伸每个区块以填满容器，造成少数字词躺在大块空底色里。组框高度由标题和行数计算。信息很少时，减少组框、扩大有用图示或重组到适当的页面，不虚构额外细节。

## 配色

| 用途 | Hex |
|---|---|
| 页面底色 | `#FAFAF7` |
| 白色表格/内容 | `#FFFFFF` |
| 正文 | `#111111` |
| 次要来源信息 | `#575D60` |
| 红色主标题/关键层边界 | `#931C25` |
| 组标题底色 | `#D9DCD8` |
| 普通条目底色 | `#ECEEEB` |
| 淡黄重点 | `#F1E8AA` |
| 细分隔线 | `#797D79` |

默认只用红、灰和淡黄：红色用于标题与少量重点，层次用位置、标签与细边界表达，不按模块轮流加蓝/青/绿。历史参考中的蓝色边界不是新页面必须保留的规则。黄色强调对应具体意义，不按每隔几行机械染色。白/灰承担大部分面积。

## 密度检查

把 v19 参考截图与输出都渲染到 1600 × 900，逐页比较：

- 正文尽早开始，几乎没有纯装饰占位。
- 组内近乎相连，依靠缩进、细线和标题带组织内容。
- 函数和释义在同一视线范围内。表格行高应与文字行数相称。
- 主体信息的字能读清，不能只有“框看起来很密”。
- 2–4 个列组仅在内容确有并列结构时使用，宽度由文字和关系决定。
- 尺寸足够仍显稀疏时，补充已有证据支持的输入、产物、分支或参数对应，或更合理地合并内容。

大圆角卡片、胶囊标签、随机彩色模块、巨大编号、阴影、宽卡间距及重复总结条会偏离本风格。不要将反例当作需要新增的装饰组件。

## 备注写法

每页备注建议包含页面所需的三类信息，按实际情况取舍：

1. 按图阅读的讲解，尤其说明分支与复用的条件。
2. 缩略 API 的完整名字、关键参数、较长含义和异常处理。
3. 本页来源：文件路径/行号、文档章节、版本；注明简化边界。

备注面向汇报者，不写“我如何做了这页”或工具日志。影响结论的条件也需要出现在正文。
